# Этап 4.10 — интеграционная проверка HTTP Range-загрузки

## Что изменено

- Сетевой перенос файла вынесен из Android-класса RuAccentModelInstaller в отдельный RuAccentHttpDownloader.
- Установщик использует этот же загрузчик; формат .part, проверка Content-Range, подсчёт байтов, синхронизация файла и переименование сохранены.
- Добавлен JVM-тест с локальным HTTP-сервером. Он проверяет реальный поток байтов, а не только планировщик HTTP-ответов.

## Проверенные сценарии

1. Полная загрузка обычным ответом HTTP 200.
2. Прерванный ответ: сохранение частичного файла и продолжение с точного смещения через Range.
3. Сервер игнорирует Range и отвечает HTTP 200: частичный файл заменяется полной копией, байты не дублируются.
4. Некорректный Content-Range: ответ отклоняется, опасный частичный файл удаляется.
5. HTTP 416: выполняется ровно одна чистая повторная загрузка с нулевого байта.

## Результат

Локальный запуск команды bash tools/run_http_download_tests.sh:

- PASS real HTTP downloader integration: 5 scenarios
- PASS truncated-response resume
- PASS ignored Range, malformed Content-Range, and HTTP 416 recovery

## Что ещё не подтверждено

Этот этап проверяет транспорт файлов. Он не подтверждает скачивание реальных 16 файлов RUAccent с Hugging Face, проверку их SHA-256, создание ONNX-сессий, качество распознавания ударений или работу на Xiaomi Redmi Note 12 Pro 4G. Следующий рубеж — воспроизвести полный сетевой install с закреплённой ревизии, затем выполнить warmUp() четырёх ONNX-моделей и проверить Android-сборку.
