## Цель и правила

Главная цель — проверить контекстное произношение каждого словоупотребления всей книги оригинальным production RuVoice, сформировать только необходимые безопасные пользовательские списки «Ударения» и «Замены», повторно прогнать всю книгу тем же RuVoice и проверить исправления и регрессии. EPUB не размечается и не переписывается; е/ё не нормализуется; системный словарь и APK-assets не заменяются пользовательскими оверлеями.

## Реализованные изменения

1. Исправлена Windows CP1252 ошибка при инициализации `ruaccent-predictor`: portable worker включает UTF-8 bootstrap до импорта модели; PyInstaller получает каталог bootstrap-модуля.
2. Родительский процесс явно декодирует stdout/stderr portable worker как UTF-8 и не зависит от Windows locale.
3. Полный режим третьей модели работает fail-closed: неполное или неожиданное множество координат словоупотреблений останавливает аудит.
4. Проверка полного контекстного отчёта больше не подменяет отсутствующий результат RUAccent базовым результатом RuVoice. Отсутствующее независимое предсказание остаётся явно отсутствующим.
5. Координаты книжного оверлея проверяются точно, а не только сравнением количества строк.
6. ZIP-пакетировщик теперь включает полный отчёт третьей модели: сводку, выровненные вхождения, расхождения, доказательства подтверждённых кандидатов и отдельную OOV-очередь. Перед упаковкой проверяется полный режим и 100% покрытие многосложных слов третьей моделью. Эти отчёты не являются файлами импорта; OOV-очередь предназначена для ручной проверки.

## Последний реальный прогон и исправление

Windows build дошёл до EPUB `8.Iskusstvo..epub` (SHA-256 совпал с манифестом), запустил оригинальный RuVoice, но smoke test остановился на `fragmented-01`: end-to-end regression fixture ожидал `ё` в слове «раздроблен». Для контекста «Если человек раздроблен…» уже существует контекстное правило, фиксирующее краткое прилагательное «раздро́блен», а не причастие «раздроблён». Fixture исправлен на `NO_YO`, а Python-тест теперь фиксирует это различие. Следующий Windows запуск должен подтвердить, проходит ли полный paired audit и дальнейшие стадии.

## Критические незакрытые критерии

- Не доказан полный прогон целевого реального EPUB именно оригинальным production RuVoice.
- Не доказан полный контекстный нормативный разбор каждого вхождения. 100% coverage реестра означает наличие строки на каждый токен, а не гарантию правильности ударения. Модели и словари — свидетельства, но не нормативный эталон; спорные, OOV и контекстно-зависимые случаи должны быть разрешены или честно оставлены в очереди.
- Не выполнен второй полный production-проход по тому же EPUB со штатными импортированными списками и пословная проверка исправлений/регрессий.
- Следовательно, пользовательский ZIP для целевой книги и корректность её звучания пока не подтверждены. Инструмент и тесты усилены, но весь пользовательский результат нельзя называть готовым.

## Безопасность репозитория — срочно

Репозиторий сейчас публичный. В `private-files/` на `main` и в рабочей ветке присутствуют EPUB, фотографии, архивы и диагностические файлы. Содержимое файлов не открывалось в рамках этой работы, но метаданные GitHub показывают, что файлы доступны как публичные repository contents.

Не добавлять эти материалы в CI/logs/artifacts. Простое удаление новым коммитом не стирает их из истории Git и возможных копий. Перед дальнейшим распространением необходимо сделать репозиторий приватным и отдельно очистить историю от личных файлов, затем проверить releases/actions artifacts и доступность прежних ссылок.
