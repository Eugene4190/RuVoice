## Уже реализовано

- Локальная browser-страница `private_book_server.py`, привязанная к `127.0.0.1`; загрузка EPUB/TXT/HTML до 256 МБ и необязательного TXT с книжными replacements.
- Проверки Host/Origin и одноразового токена формы; HTTP access-log отключён, чтобы не записывать имена книг и текст.
- Входные EPUB и TXT временно хранятся в локальной папке `incoming`; файлы удаляются до того, как страница покажет ссылку на ZIP.
- Запуск через launcher-файлы: Windows — `Start_RuVoice_Book_Tool_Windows.bat`; macOS/Linux — `bash start_ruvoice_book_tool.sh`. Сейчас требуется Python 3.11+ и полный checkout проекта. Самостоятельного приложения/EXE без Python пока нет.
- Append-only мастер хранится вне Git: `~/.ruvoice-book-workflow` (Windows: `%USERPROFILE%\\.ruvoice-book-workflow`). История хранит SHA-256 книг, происхождение новых слов и книги, в которых они встречались. Локальное хранилище не зашифровано.
- Кандидаты автоматически добавляются в мастер только после фильтров разрешённых источников, точного написания, е/ё, контекстных правил и конфликтов. Предыдущее утверждённое ударение не перезаписывается.
- SHA-256 делает повторную обработку той же книги идемпотентной. Исходная дельта сохраняется для восстановления ZIP, но инструкция запрещает повторно импортировать уже имеющийся список.
- ZIP содержит отдельную дельту текущей книги, полный накопительный snapshot, историю, отдельный файл replacements, инструкцию импорта и отчёты конфликтных/неизвестных форм.
- Replacements сохраняются отдельно для каждой книги. Встроенный автоматический выбор пока ограничен небольшим curated-набором уже проверенных фраз; новые пользовательские правила можно приложить TXT. Универсального автоматического извлечения новых фразовых замен пока нет.
- EPUB разбирается в порядке OPF spine; есть fallback для EPUB без корректной package metadata.

## Граница приватности — важно

- Репозиторий `Eugene4190/RuVoice` публичный. В `main` уже находится `private-files/8.Iskusstvo..epub`, а также старые материалы paired-evaluation. Название папки `private-files` не означает закрытый доступ.
- Новые пользовательские книги, замены и отчёты нельзя добавлять в Git, PR, Issues, Actions artifacts или логи.
- Новая локальная страница обрабатывает пользовательские загрузки на этом компьютере и не отправляет их в GitHub. Однако мастер, ZIP и derived review-файлы сохраняются локально без шифрования.
- Если старый EPUB в публичном репозитории является личным/закрытым, его нужно считать уже раскрытым. Удаление файла из текущего состояния не стирает старые Git-коммиты; полная очистка истории требует отдельного согласованного переписывания истории.
