## Что именно строится

Windows-программа, в которой пользователь выбирает EPUB, а инструмент:

1. Извлекает все словоупотребления оригинальным production RuVoice.
2. Сохраняет позицию и контекст каждого вхождения.
3. Сверяет произношение с RUAccent, AOT, Wiktionary и независимой третьей моделью.
4. Разделяет безопасные книжные исправления, контекстные исключения, неоднозначные формы и OOV.
5. Формирует отдельные пользовательские списки RuVoice «Ударения» и «Замены».
6. Повторно прогоняет всю книгу оригинальным RuVoice с итоговыми списками — даже если файл автоматически подтверждённых поправок пуст.
7. Проверяет весь второй реестр на пропуски и регрессии и упаковывает ZIP для импорта.

Исходный EPUB не переписывается. Системный словарь RuVoice не изменяется.

## Последние исправления в Git

- Windows worker запускает Python-модели с UTF-8 и явно декодирует их вывод, не полагаясь на CP1252.
- Полный аудит третьей модели проверяет координаты каждого многосложного вхождения; отсутствие результата не маскируется исходным RuVoice.
- Книжные оверлеи проверяются по точным координатам вхождений.
- Regression fixture для фразы «Если человек раздроблен…» исправлен: здесь контекстное краткое прилагательное «раздро́блен», а не причастие «раздроблён». Проверка больше не навязывает ошибочное `ё`.
- Второй полный production-проход теперь обязателен независимо от количества автоматически подтверждённых исправлений. Добавлен отдельный unit test этого поведения.
- Windows workflow запускается при изменении кода полного книжного workflow и соответствующих regression-данных.

## Что ещё нельзя объявлять готовым

Предыдущий реальный прогон дошёл до книги и остановился на противоречивом regression fixture для «раздроблен». Исправление зафиксировано и Python tests прошли, но новый end-to-end Windows run ещё не подтвердил итоговый ZIP.

Количество автоматических поправок для всей книги пока не подтверждено. Генератор намеренно добавляет в импорт только слова, для которых согласуются все вхождения, две словарные базы и независимая модель; неоднозначные случаи остаются в реестре и очереди проверки. Количество строк не должно искусственно увеличиваться за счёт сомнительных замен.

Отдельный архив с 21 ручной записью, созданный ранее в чате, — только небольшой seed-набор. Он не является результатом полного аудита и не должен позиционироваться как готовые словари книги.

## Критерий завершения

Проект можно считать готовым для чтения книги только когда Windows run завершится успешно, будет доступен portable ZIP приложения, а upload-to-ZIP обработка целевого EPUB подтвердит:

- 100% покрытие исходных словоупотреблений;
- полный отчёт независимой модели без пропусков;
- обязательный второй полный проход оригинальным RuVoice;
- отсутствие пропусков и необъяснённых регрессий во втором реестре;
- ZIP с импортируемыми списками и отчётами, с отдельным количеством записей и разбором неоднозначностей.

До выполнения этих критериев нельзя обещать, что ударение исправлено во всей книге.
