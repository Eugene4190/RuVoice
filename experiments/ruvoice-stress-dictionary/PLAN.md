# План реализации RuVoice: полный контекстный контроль произношения EPUB

**Нормативная постановка:** сначала прочитать [USER_REQUIREMENTS.md](USER_REQUIREMENTS.md), затем [PRODUCT_GOAL.md](PRODUCT_GOAL.md). Если старый скрипт, README, отчёт или эксперимент противоречит этим требованиям, старый материал не является указанием к действию.

**Цель:** пользователь загружает EPUB и получает готовые пользовательские списки для правильного чтения всей книги оригинальным RuVoice. Текст книги не размечается и не переписывается.

Рабочая ветка: stress-dictionary-pipeline. PR #1 остаётся Draft; main не менять и не сливать без отдельного разрешения.

## Порядок работ — без параллельных отвлечений

### 1. Подтвердить исходный RuVoice
- Зафиксировать точный upstream commit/версию оригинального production RuVoice, соответствующую пользовательской версии.
- Проверить штатный путь чтения: EPUB/text extraction, replacements, tokenizer/segmenter, accentuation, встроенные и пользовательские словари, приоритеты и порядок применения.
- Подтвердить фактические форматы и семантику списков «Ударения» и «Замены».
- Не считать экспериментальную копию, RUAccent или новый predictor исходным движком.
- Результат этапа: краткая техническая карта production pipeline, воспроизводимый invocation и golden smoke test на словах/фразах с известным контекстом.

### 2. Полный исходный прогон всей книги
- Запустить весь EPUB через подтверждённый оригинальный RuVoice, а не только через scanner/candidate builder.
- Сохранить выравнивание каждого исходного токена с его положением и контекстом, включая слова вне любых внешних словарей.
- Сохранить результат произношения/расстановки ударения, который реально выдаёт RuVoice.
- Подтвердить отсутствие потерь, перестановок, склейки/разрезания токенов при обработке EPUB.
- Результат: полный baseline и per-occurrence ledger с 100% покрытием исходных словоупотреблений.

### 3. Проверить каждое словоупотребление по контексту
Для каждого токена определить нормативное чтение и сопоставить его с baseline RuVoice:
- часть речи, лемма и морфологическая форма;
- значение в предложении, синтаксическая роль и соседние слова;
- устойчивые выражения, имена и термины;
- допустимые нормативные варианты;
- независимые подтверждения/опровержения из надёжных словарей и моделей.

AOT, Wiktionary, RUAccent и дополнительные predictor-модели — свидетельства для проверки, а не границы поиска и не ground truth. Приоритет — реальные употребления в книге и смысл контекста. Частотность используется только для очередности анализа.

Результат: для каждого токена сохранены baseline, проверенное чтение, основание и решение: baseline верен / нужна коррекция / контекстный вариант / случай неоднозначен. Случай неоднозначен — не прятать в «исправлено» и не угадывать.

### 4. Сформировать только необходимые исправления
- Не переписывать EPUB.
- Для подтверждённых словарных ошибок создать записи в поддерживаемом пользовательском списке «Ударения».
- Для омографов и фразовых/контекстных случаев создать безопасные правила «Замены», ограниченные соответствующим контекстом.
- Не дублировать правильное поведение встроенного RuVoice.
- Не создавать общие записи из книжных исключений.
- Перед включением записи проверить её формат, область действия, приоритет, пересечение с системными/пользовательскими списками и возможные побочные срабатывания.

### 5. Повторно прогнать весь EPUB через тот же RuVoice
- Включить созданные пользовательские списки в штатном порядке.
- Повторить полный production проход по всей книге.
- Сравнить каждый токен с проверочным реестром.
- Проверить, что намеченные ошибки исправлены, верные baseline чтения не испорчены, контекстные правила не срабатывают вне контекста, текст EPUB не изменился.
- Результат этапа — полный regression report с числом подтверждённых исправлений и числом оставшихся неоднозначных случаев.

### 6. Выдать готовый пользовательский пакет
ZIP должен содержать:
- TXT для импорта в «Ударения» — только нужные новые исправления;
- TXT для «Замены» — только необходимые книжные/контекстные правила;
- отчёт о полном покрытии и результате проверки каждого слова;
- короткую инструкцию импорта.

Постоянный накопитель универсальных одобренных словарных форм может существовать, но это вспомогательная функция. Он не заменяет проверочный реестр и не должен перезаписывать записи при конфликтах. Книжные исключения хранятся отдельно.

## Критерии завершения

1. 100% исходных словоупотреблений присутствуют в проверочном реестре.
2. У каждого вхождения есть контекст, результат оригинального RuVoice и решение проверки.
3. Исправления применены штатными пользовательскими механизмами RuVoice.
4. Весь EPUB повторно обработан оригинальным RuVoice с новыми списками.
5. Регрессии проверены по каждому вхождению, не только на sample/seed list.
6. Видимый текст и исходный EPUB не изменены; нет значков ударения/плюсов/фонетической переписи; нет нормализации е/ё.
7. Пользователь получает понятный ZIP без CLI и ручного редактирования.

Пока хотя бы один из этих пунктов не выполнен, инструмент не описывать как готовый.

## Что не делать без отдельной необходимости

- Не продолжать расширение маленького candidate pool как основной способ нахождения ошибок.
- Не путать процент словарного покрытия с точностью ударений.
- Не считать diff между RuVoice и RUAccent списком реальных ошибок.
- Не запускать сторонние модели на всю книгу только ради дополнительных отчётов, если не определено, какую часть проверки каждого токена они усиливают.
- Не скачивать новые гигантские корпуса без конкретного применения к словоупотреблениям этой книги.
- Не заниматься APK/Android/Gradle и другими задачами, не влияющими на чтение книги в текущем оригинальном RuVoice.
- Не просить пользователя вручную тестировать заведомо незавершённый алгоритм.

## Следующий шаг с наивысшим приоритетом

Провести аудит уже имеющегося кода и отчётов относительно пунктов 1–2: выяснить, существует ли воспроизводимый способ прогнать EPUB через точный оригинальный production RuVoice и получить результат для каждого токена. Если нет — сначала реализовать именно это. Не начинать с нового словаря, третьего predictor или большого review pipeline.
