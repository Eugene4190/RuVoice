# План проекта RuVoice: персональное чтение книг с качественной озвучкой

**Главная цель:** пользователь загружает книгу → получает готовое дополнение словаря именно для этой книги → импортирует его в RuVoice → читает и одновременно слушает качественную озвучку. Следующая книга проходит тот же процесс без изменений кода и ручной работы в Git.

**Это личный пользовательский инструмент, а не академическое исследование русского ударения.** Точный продуктовый сценарий и критерии приёмки зафиксированы в PRODUCT_GOAL.md. При конфликте старых исследовательских заметок с этим сценарием приоритет у PRODUCT_GOAL.md.

**Рабочая ветка:** stress-dictionary-pipeline  
**PR:** [#1 — Draft](https://github.com/Eugene4190/RuVoice/pull/1)  
**Граница изменений:** не менять main, системный словарь и глобальные пользовательские данные без отдельного обоснования.

## Что строим

Один повторяемый процесс для любой новой EPUB-книги:

1. Пользователь загружает EPUB в приватную точку загрузки.
2. Pipeline анализирует текст, словоформы и контекст.
3. Pipeline читает постоянный личный накопительный словарь из всех предыдущих книг; уже добавленные формы не дублируются, а в хранилище добавляются только новые безопасные записи.
4. Создаётся дельта новых словарных записей для текущей книги, которая импортируется в RuVoice отдельным списком; старые списки книг остаются включёнными.
5. Пользователь скачивает ZIP: дельта текущей книги, полный накопительный TXT-снимок, контекстные замены при необходимости, инструкция и отчёт.
6. После безопасной проверки дельта пополняет постоянный личный накопитель; старые записи никогда не очищаются и не заменяются новой книгой.
7. Пользователь импортирует дельту, открывает книгу и читает её одновременно с озвучкой.
8. Для следующей книги процесс повторяется с учётом всего накопленного словаря.

Пользователь не должен запускать Python, вручную запускать GitHub Actions, копировать книгу в репозиторий или редактировать TXT.

## Приоритеты реализации

### 1. Постоянный накопительный личный словарь
- Хранить личный словарь в приватном постоянном хранилище, независимом от временной папки обработки книги.
- Каждая новая книга пополняет существующий словарь, а не пересоздаёт его с нуля.
- Использовать точную словоформу и ударную форму как ключ записи; одинаковые записи дедуплицировать, сохраняя provenance и список книг-источников.
- Повторная обработка одной и той же книги должна быть идемпотентной: никаких повторных строк.
- Если новая книга предлагает конфликтующее ударение для уже утверждённой формы, не перезаписывать старое автоматически; отправлять конфликт в отчёт/отдельное книжное правило.
- Хранить отдельную дельту текущей книги и полный накопительный экспорт для резервного копирования/восстановления.
- Импортировать дельту в RuVoice отдельным списком с названием книги, не удаляя и не выключая предыдущие книжные списки.
- Контекстные фразовые замены вести по книге/контексту, не объединять без проверки на побочные эффекты.

### 2. Приватный вход и отдельная обработка каждой книги
- Принимать пользовательский EPUB через одну понятную точку загрузки.
- Не хранить личную книгу в публичном Git и не публиковать её содержимое в CI-логах/артефактах.
- Обрабатывать каждую книгу во временном или приватном изолированном каталоге.
- Хранить идентификатор/хеш книги, чтобы не смешивать дополнения разных книг.

### 3. Качественное книжное дополнение
- Сначала учитывать встроенный словарь RuVoice и уже импортированные/утверждённые записи.
- Находить только словоформы, реально встречающиеся в этой книге и требующие дополнения.
- Сохранять точное написание, е/ё, часть речи, грамматические признаки, контекст и provenance.
- Использовать AOT, Wiktionary и другие доступные источники как свидетельства; совпадение источников — сигнал, но не абсолютная гарантия.
- Различать омографы, варианты нормы, формы прилагательных/причастий, служебные слова и фразовое ударение.
- Не угадывать конфликтные и неоднозначные формы. Лучше оставить штатное поведение RuVoice и показать предупреждение, чем добавить вредное исправление.
- Учитывать частотность только для приоритизации проверки, не как вероятность правильного ударения.

### 4. Готовый пакет импорта
Для каждой книги автоматически собирать ZIP:
- <book>_new_stress.txt — только новые записи этой книги для RuVoice → «Ударения»; импортировать как отдельный список, не удаляя списки прошлых книг;
- MyBooks_Cumulative.txt — полный накопительный личный словарь со всеми безопасно добавленными записями из всех книг (резервный экспорт/восстановление);
- <book>_replacements.txt — контекстные правила для RuVoice → «Замены», если они необходимы; оставлять привязанными к книге, если они не универсальны;
- IMPORT.txt — короткая пошаговая инструкция;
- отчёт по покрытию, количеству новых и накопленных форм, конфликтам и отложенным случаям.

Файлы должны импортироваться без ручного исправления формата. Сохранённые личные записи пополняются append-only: новая книга не может очистить накопленное. Книжные записи не попадают автоматически во встроенный глобальный словарь RuVoice.

### 5. Чтение и озвучка
- Использовать штатный production-путь RuVoice и доступные модели/корректор для максимально качественного произношения.
- Проверять ударения, омографы, е/ё, контекстные замены и границы слов на полном тексте книги.
- Проверить, что текст книги остаётся целым и в правильном порядке, а воспроизведение не обрывается и позволяет следить по тексту.
- Не менять движок озвучки без конкретного воспроизводимого улучшения для чтения пользователя.

### 6. Повторяемость
- Проверить полный пользовательский путь на двух разных EPUB.
- Вторая книга должна обрабатываться тем же интерфейсом, без изменения кода и без переноса ошибок/исключений из первой книги.
- Результаты и контекстные замены каждой книги должны оставаться раздельными; общие безопасные word-level записи пополняют единый личный накопитель.
- Проверить сценарий: книга A добавляет записи A; книга B сохраняет A и добавляет B; повтор книги B не создаёт дубликаты; конфликт B не затирает A.

## Не является блокером завершения

- Внешний независимый лингвист для каждой книги.
- Академически репрезентативный gold set и публикация метрики precision/accuracy.
- Скачивание и полная обработка всего Викисловаря как самоцель.
- Построение универсального словаря всех русских слов.
- APK-релиз/публикация приложения, если изменения приложения не требуются для приёмки чтения и озвучки.

Внутренние gold seed, AOT-аудит, лицензирование источников и расширенные корпусные исследования можно сохранять как инструменты качества. Они не должны подменять основную задачу и блокировать личный сценарий, когда конкретная книга уже читается качественно.

## Технические ограничения и безопасность

- main не изменять; PR не сливать без отдельного решения пользователя.
- Не менять production Системный.txt, глобальные замены и APK assets ради одной книги. Личный накопительный словарь — отдельное приватное хранилище; его единственная задача — пополняться между книгами.
- Пользовательские книги не помещать в публичный Git, публичные Actions artifacts или логи. Текущая reference-книга в репозитории — тестовый материал, не образец хранения будущих пользовательских загрузок.
- Сомнительные исправления показывать отдельно и не выдавать за достоверные.
- Любые изменения pipeline сопровождать автоматическими тестами и записью результата в PROGRESS.md.
