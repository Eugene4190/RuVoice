# Продуктовая цель RuVoice: книга → дополнение словаря → чтение и озвучка

**Владелец и основной пользователь:** автор проекта, личное использование. Это не академический корпус и не публичный лингвистический сервис.

## Зачем существует проект

Пользователь берёт новую книгу, загружает её в одно понятное место, получает готовое дополнение словаря именно для этой книги, импортирует его в RuVoice и читает книгу, одновременно слушая максимально качественную озвучку. Для следующей книги он повторяет тот же простой процесс — без разработки, ручного запуска скриптов и редактирования Git.

Главный результат проекта — не количество собранных слов и не научный отчёт. Главный результат — удобное и качественное чтение конкретной книги в RuVoice.

## Целевой пользовательский сценарий

1. Пользователь открывает одну понятную точку загрузки и выбирает EPUB-книгу (другие форматы можно добавить после рабочего EPUB-сценария).
2. Сервис принимает книгу и обрабатывает её в отдельном временном рабочем каталоге.
3. Pipeline извлекает реальные словоформы и контекст книги, учитывает встроенный словарь RuVoice, уже утверждённые дополнения, морфологию, AOT/Wiktionary и доступные проверенные источники.
4. Pipeline сначала загружает постоянный личный накопительный словарь, созданный всеми предыдущими книгами, затем формирует дополнение текущей книги только из новых безопасных записей. Старые записи никогда не удаляются и не заменяются новой книгой.
5. Пользователь получает один ZIP-пакет для скачивания.
6. В пакете есть:
   - TXT-файл новых словарных ударений только для текущей книги (дельта) — для импорта в RuVoice отдельным списком;
   - полный TXT-снимок личного накопительного словаря со всеми ранее добавленными книгами — для резервной копии и восстановления;
   - TXT-файл контекстных/фразовых замен для вкладки «Замены», если такие правила нужны книге;
   - короткая инструкция, куда импортировать каждый файл и как включить списки;
   - понятный отчёт: что добавлено, какие конфликты исключены и какие редкие/неоднозначные случаи оставлены без автоматического исправления.
7. Пользователь импортирует дельту текущей книги в RuVoice как новый отдельный список с названием книги; уже импортированные списки предыдущих книг остаются включёнными. Полный накопительный TXT хранится как резервная копия/источник восстановления, а не как команда удалить старые записи.
8. Для следующей книги pipeline читает весь накопительный личный словарь, исключает уже известные записи и добавляет только новые. Новая дельта и обновлённый полный снимок включают все прошлые утверждённые записи. Повторная обработка той же книги не создаёт дубликатов.

**Обязательные свойства:** (а) личный словарь накапливается от книги к книге и не обнуляется; (б) каждое дополнение текущей книги содержит только новые записи; (в) конфликт новой формы с уже утверждённой записью не перезаписывает старую автоматически; (г) для повторной книги не требуется менять код, создавать commit, вручную копировать EPUB в репозиторий или просить ChatGPT заново объяснить процесс.

## Требования к качеству

- Максимально качественное ударение достигается сочетанием встроенного RuVoice, морфологии, точного написания е/ё, контекста, книжного дополнения и безопасных фразовых замен.
- Учитывать часть речи, грамматическую форму, омографы, имена, варианты нормы, дефисные формы и границы слов.
- Не добавлять в пользовательский словарь неподтверждённые догадки только ради большего покрытия. Сомнительную форму лучше оставить штатной модели RuVoice и явно отметить в отчёте, чем уверенно испортить озвучку.
- Для каждого автоматически добавленного исправления сохранять источник и причину выбора. Это нужно для диагностики и исправления ошибок, а не для публикации научной метрики.
- Если у слова есть нормативные варианты, не считать один допустимый вариант ошибкой автоматически.
- Учитывать качество самого воспроизведения: использовать штатный production-путь озвучки RuVoice и его доступные модели/корректор; не ломать сегментацию, порядок текста и синхронное чтение с прослушиванием.
- Вести постоянный личный накопительный словарь в приватном хранилище; пополнять его безопасными новыми записями после каждой книги.
- Хранить историю происхождения каждой записи и список книг, в которых она встретилась.
- Обрабатывать контекстные/фразовые замены отдельно по книге, если их объединение может изменить произношение в другом контексте.
- Не менять встроенный Системный.txt и APK assets ради одной книги.

## Критерии готовности продукта

- [ ] Есть одна доступная пользователю точка загрузки книги с понятной кнопкой запуска обработки; пользователю не нужно запускать Python, GitHub Actions или редактировать файлы вручную.
- [ ] На выходе автоматически появляется скачиваемый ZIP с дельтой текущей книги, полным накопительным словарём и короткой инструкцией.
- [ ] Личный накопительный словарь хранится постоянно и дополняется после каждой книги; новые книги не удаляют старые записи.
- [ ] В RuVoice новые дельты импортируются отдельными списками, чтобы списки предыдущих книг оставались активными.
- [ ] Словарный TXT импортируется в RuVoice → «Ударения», а файл замен — в RuVoice → «Замены»; списки включаются без ручного редактирования строк.
- [ ] Проверено на полном EPUB: книга обрабатывается целиком, не теряет текст, не путает порядок фрагментов и не создаёт опасных замен на границах слов.
- [ ] После импорта пользователь может открыть ту же книгу в RuVoice, читать текст и одновременно слушать озвучку; проверены произношение ударений, проблемные омографы, е/ё и непрерывность воспроизведения.
- [ ] Две разные книги обработаны подряд: итоговый накопительный словарь содержит безопасные добавления обеих книг, а пакет второй книги содержит только её новые записи.
- [ ] Повторная обработка той же книги не создаёт дубликатов и не стирает ранее накопленное.
- [ ] Конфликтующая новая запись не перезаписывает старую утверждённую запись молча.
- [ ] Пользовательские книги и контекст не попадают в публичный Git, публичные Actions artifacts, логи или отчёты. Временные файлы удаляются после обработки либо хранятся только в явно выбранном пользователем приватном хранилище.
- [ ] Ошибки, конфликты и неизвестные случаи отражаются в отчёте; pipeline не выдаёт отсутствие записи за доказательство ошибки модели.

## Что НЕ является критерием завершения

- Внешний независимый лингвист или «комиссия» для проверки каждой книги.
- Академически репрезентативный gold set, публикация precision/accuracy или доказательство стопроцентной точности русского языка.
- Полный дамп всего Викисловаря как самоцель.
- Универсальный словарь всех существующих русских слов и форм.
- Полировка APK, публикация в магазине или релиз, если они не нужны для того, чтобы текущий RuVoice читал и озвучивал книгу.
- Новые исследовательские направления, не улучшающие пользовательский сценарий выше.

Внутренние gold-тесты, AOT/Wiktionary-аудит, лицензирование источников и тесты е/ё остаются полезными инженерными средствами. Они должны помогать безопасному чтению, но не превращаться в отдельные обязательные проекты и не блокировать работу без связи с реальной ошибкой в пользовательском сценарии.

## Реальное состояние на 2026-11-25

Уже есть основа генерации книжного дополнения: build_book_dictionary.py, анализатор книги, проверка источников и разделение кандидатов/конфликтов/отложенных форм. GitHub Actions #280 успешно собрал тестовый артефакт для хранящейся в репозитории книги 8.Iskusstvo..epub.

В этом запуске обработано 62 848 словоупотреблений и 14 166 уникальных словоформ; 291 вхождение уже покрывается встроенным словарём, найден 1 новый кандидат и 4 формы удержаны контекстными правилами. Это подтверждает работу базового книжного сборщика, но ещё не подтверждает готовность конечного пользовательского сценария.

Пока отсутствует подтверждённая единая приватная точка загрузки произвольной новой книги и готовый ZIP-пакет для пользователя. Также ещё не зафиксирован практический приёмочный проход «загрузил → скачал → импортировал → читаю и слушаю» на двух разных книгах.

## Порядок реализации

1. Сделать приватное постоянное хранилище личного накопительного словаря. Хранить точные записи, provenance и историю добавления; операции добавления должны быть append-only, идемпотентными и защищёнными от тихой перезаписи конфликтов.
2. Сделать книжную обработку независимой от файла, закоммиченного в репозитории. Вход — загруженный пользователем EPUB; pipeline читает весь накопительный словарь и выдаёт дельту только для этой книги.
3. Собрать единый пакет результата: дельта текущей книги, полный накопительный TXT-снимок, контекстные замены при необходимости, инструкция импорта, отчёт и список удержанных неоднозначностей.
4. Добавить простую приватную точку загрузки. Один файл → одна кнопка «Собрать дополнение» → скачать ZIP. Технологию интерфейса выбирать по кратчайшему надёжному пути; не строить большую платформу.
5. Пройти реальный цикл в RuVoice. Импортировать дельту новой книги отдельным списком, открыть исходную книгу, проверить чтение и одновременную озвучку на реальном устройстве.
6. Повторить на второй книге и проверить, что накопитель сохранил первую дельту, добавил вторую без дубликатов, а повторный прогон не меняет результат.
6. После приёмки заморозить scope. Оставить дальнейшее расширение корпусов и универсального словаря отдельной будущей работой.
