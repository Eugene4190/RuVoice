# Продуктовая цель RuVoice: правильное произношение всей книги

**Главная пользовательская задача:** взять EPUB и добиться того, чтобы оригинальный RuVoice правильно произносил каждое слово с учётом контекста. Пользователь должен слушать книгу, а не видеть редакторскую разметку ударений.

**Обязательные требования:** [USER_REQUIREMENTS.md](USER_REQUIREMENTS.md). Этот файл и USER_REQUIREMENTS.md — нормативная постановка задачи; старые экспериментальные отчёты и ограничения текущих скриптов не могут сужать её.

## Главный результат

Готовая книга звучит максимально правильно через исходный production RuVoice. Пользователь импортирует в RuVoice подготовленные пользовательские списки «Ударения» и, где нужно, «Замены». Сам EPUB остаётся в исходном написании.

Это не проект по созданию нового движка, не исследование словарей и не задача увеличить число записей. Все инструменты подчинены качеству произношения в оригинальном RuVoice.

## Неприкосновенные ограничения

1. **Исходный движок:** использовать оригинальный production RuVoice, его штатные модели, системные ресурсы и реальный порядок обработки. Не подменять его сторонней моделью или экспериментальным форком.
2. **Книга визуально не размечается:** не вставлять ударения/плюсы/диакритики в EPUB, не переписывать слова фонетически и не менять содержимое.
3. **Е/Ё:** не выполнять массовые или автоматические преобразования «е» ↔ «ё». Пользователь не просил эту задачу.
4. **Полнота:** проверять каждое словоупотребление всей книги, а не только кандидаты из ограниченного словаря.
5. **Контекст:** разрешать омографы и формы по значению и предложению, не применять глобальные правила там, где чтение зависит от контекста.
6. **Безопасные изменения:** добавлять только обоснованные исправления в поддерживаемые пользовательские списки RuVoice; не трогать системный словарь, APK и движок без отдельной необходимости.
7. **Повторная проверка:** обязательно повторно прогонять всю книгу через тот же оригинальный RuVoice с добавленными списками и проверять исправления и регрессии.

## Правильная архитектура

### A. Полный исходный проход через RuVoice
- Зафиксировать версию исходного RuVoice и порядок применения встроенных/пользовательских словарей, замен, сегментации и акцентуации.
- Прогнать все главы и абзацы EPUB по реальному production pipeline без сторонних подмен.
- Сформировать выравнивание всех исходных словоупотреблений с тем, что выдаёт RuVoice.

### B. Полный проверочный реестр произношения
Для каждого слова и каждого вхождения записать исходную форму, позицию в книге, контекст, выбор RuVoice, проверенное контекстное ударение/чтение, основания проверки и статус. Реестр должен покрывать 100% словоупотреблений.

Реестр включает и правильные решения штатного движка. Проверка не ограничивается формами, найденными в словарях. Неизвестная словарю форма всё равно подлежит контекстной проверке.

### C. Контекстная проверка
Сочетать морфологию, нормативные словари, словари вариантов, контекст и независимые модели. Ни модель, ни отдельный словарь не являются безусловным эталоном. Расхождение — повод проверить контекст, а не автоматическое доказательство ошибки.

### D. Слой исправлений для RuVoice
- Если исходное решение верное, оставить его и не создавать лишнюю запись.
- Если подтверждённая ошибка — создать точную запись в штатном списке «Ударения».
- Если чтение зависит от конкретного контекста — создать поддерживаемое контекстное правило в «Замены», ограниченное нужным выражением/книжным контекстом.
- Не смешивать книжные исключения с глобальными словарными формами.
- Проверять, что формат пользовательского списка действительно поддерживается выбранной версией приложения.

Таким образом, **проверочный реестр охватывает каждое слово, а импортируемый словарь содержит только необходимые переопределения**. Не нужно принудительно дублировать все правильные решения встроенного RuVoice в пользовательском списке — это могло бы навредить его собственной логике.

### E. Полный контрольный проход
Снова прогнать весь EPUB через оригинальный RuVoice с подготовленными пользовательскими списками. Пословно сопоставить результат с проверочным реестром. Подтвердить, что ошибки исправлены, правильные решения сохранены, контекстные исключения не протекают в другие значения, а текст книги не изменился.

### F. Удобный пользовательский сценарий
Двойной щелчок по Windows BAT/portable EXE → локальная страница → загрузка EPUB → обработка → ZIP. В ZIP — готовая дельта «Ударения», книжные «Замены» при необходимости, отчёт о полном охвате/проверке и инструкция импорта. Никакой ручной работы с CLI, словарными корпусами или GitHub Actions.

## Критерии готовности

- [ ] Точная production-версия оригинального RuVoice и порядок всех этапов подтверждены.
- [ ] Первый проход действительно использует оригинальный RuVoice на полном EPUB.
- [ ] Реестр содержит запись для каждого словоупотребления; coverage = 100% по токенам исходной книги.
- [ ] Для каждого токена определено ожидаемое произношение/ударение в его контексте; неразрешённые случаи перечислены отдельно и не скрыты в статистике.
- [ ] Все подтверждённые ошибки представлены безопасными записями в штатных пользовательских форматах.
- [ ] Повторный проход всей книги через тот же оригинальный RuVoice подтверждает исправления и отсутствие регрессий.
- [ ] Исходный EPUB и видимый текст остаются неизменными; знаки ударения и фонетическая перепись в книгу не добавляются; «е/ё» не нормализуются.
- [ ] ZIP можно импортировать в RuVoice без ручного редактирования файлов.
- [ ] Сквозной пользовательский процесс проверен на полном реальном EPUB до того, как инструмент называется готовым.

## Что не является целью или критерием успеха

- Накопление максимально большого словаря само по себе.
- Полный дамп Wiktionary или другого корпуса.
- Сравнение десятков моделей без проверки реального чтения RuVoice.
- Создание нового синтезатора или замена RuVoice на RUAccent.
- Изменение орфографии книги, вставка ударений и фонетическая перепись текста.
- Переработка APK/Gradle/Android, если она не нужна для пользовательского импорта списков.
- Новые форматы книг, облачный сервис, публичная платформа или академический gold-корпус.
- Большие отчёты и дополнительные библиотеки, не ведущие напрямую к проверке конкретных слов в полном контексте.

## Честное текущее состояние на 2026-11-26

В репозитории уже есть прототип локального загрузчика, Windows portable EXE, сборка ZIP, словарные скрипты, парные анализаторы и экспериментальный третий модельный проход. Это полезная инфраструктура, но она **не доказывает правильность ударений всех слов книги и не удовлетворяет основную цель**.

Прежний полнокнижный прогон сравнивал production RuVoice с RUAccent и словарными источниками; 64 559 токенов и 14 199 словоформ были обработаны в одном из прежних отчётов. Это не было полной проверкой правильности каждого токена. Небольшое число найденных расхождений также не означает, что остальные слова доказанно верны. Новый третий модельный проход на момент checkpoint 2026-11-25 не был подтверждён полным прогоном на реальной книге.

Поэтому текущие сборщики кандидатов и модели нельзя считать законченным алгоритмом. Следующий инженерный шаг — сначала подтвердить точный оригинальный production pipeline и построить полный по-вхождению проверочный реестр, а затем только добавлять безопасные исправления.
